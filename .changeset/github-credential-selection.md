Tighten GitHub credential selection so setup never silently acts as a different account. Workflow-file writes and workflow dispatches only fall back to the stored keyring credential when the failure names a missing `workflow` scope, no account was explicitly selected, and the command was not killed by its timeout, so a dispatch of unknown outcome is never re-sent and an explicit selection is always honored; the environment-secret write no longer retries as the machine-wide account and reports the real refusal with account guidance instead. The injected session token is now recognised only by an exact `GH_TOKEN`/`GITHUB_TOKEN` source, so a stored `oauth_token` credential is no longer mistaken for it, the acting `workflow` scope is read from the credential the strategy actually selected when one login is signed in twice, and the GitHub Packages credential reports the source it truly resolved — including the injected-token fallback taken when the keyring lookup yields nothing — so the dialog and the GHCR preflight describe the credential that will be used. A restored account selection that gh no longer knows is ignored rather than obeyed, and surfaced with a path back to choosing an account. Scope guidance now keeps the `workflow` remediation alongside the packages warning and only suggests selecting a stored account when a switchable, package-capable account exists, recommending `gh auth login` with the package scopes otherwise.

# Radius — App Graph

Build and display the Radius application graph for a repo. The graph is generated by `rad graph build` on the deploy workflow and rendered in the `radius` canvas using Cytoscape.

## When to use this skill

- "Show me the app graph"
- "What resources are in my Radius app?"
- "Compare the graph for PR #N"
- "Refresh the graph after my latest deploy"
- "What changed in the graph between branches?"

## Data flow

1. The deploy workflow (`.github/workflows/radius-deploy.yml`) runs `rad graph build --orphan-branch radius-graph --source-branch <branch>` after every successful deploy.
2. This writes `<branch>/app.json` to the orphan branch `radius-graph` in the same repo.
3. The popup reads `radius-graph/<branch>/app.json` via the GitHub Contents API and renders it with Cytoscape + dagre.
4. PR diff mode compares the PR head branch graph against the base branch graph; resources are tagged `added | removed | modified | unchanged`.

## Rendering features

The renderer ports the production improvements from `radius-project/github-extension@brooke-hamilton/graph-dev`:

- **Diff coloring** — `added` (green), `removed` (red), `modified` (yellow), `unchanged` (grey). Node border + subtle bg fill.
- **Deployment-state styling** — `provisioningState` overrides diff color so a live deploy is visible:
  - `Queued` → dashed grey border, 55% opacity
  - `InProgress` → bold yellow border + yellow fill
  - `Failed` → bold red border + red fill
  - `Succeeded` → falls back to diff coloring
- **Cross-edge classification** — edges that point to a same-rank or backward-rank node (cycles, lateral links) render as **dashed red** instead of the default grey arrow; helps spot non-DAG structure at a glance.
- **Configurable edge curve** — `renderGraph({ curveStyle })` accepts any Cytoscape curve type (`bezier`, `straight`, `taxi`, `segments`, etc.). Defaults to `bezier`. Exported as `CURVE_STYLES` for UI pickers.

## How to invoke

When the user asks to see, build, refresh, or compare the application graph, **open the canvas straight to the graph view**:

```
open_canvas({
  canvasId: "radius",
  instanceId: "radius-panel",
  input: { page: "graph", repo: "<owner/repo>" }
})
```

For PR diff mode:

```
open_canvas({
  canvasId: "radius",
  instanceId: "radius-panel",
  input: { page: "graph-diff", repo: "<owner/repo>", baseBranch: "main", headBranch: "<pr-branch>" }
})
```

The canvas will:
- Show the **live deployed graph** if `radius-graph/<branch>/app.json` exists.
- Otherwise fall back to a **static preview parsed from `.radius/app.bicep`** on the default branch (so the graph is visible before any deploy happens).
- Show "no graph available" only if neither source exists — in that case, prompt the user to create a bicep file (`radius-app-bicep` skill) or run a deploy (`radius-deploy` skill).

## Prerequisites

- For the **static preview**: `.radius/app.bicep` on the default branch (use the `radius-app-bicep` skill if missing).
- For the **live graph**: at least one successful Radius deploy run (so `radius-graph` orphan branch and `<branch>/app.json` exist). Use the `radius-deploy` skill to deploy.
- The popup's "Refresh" button repulls `app.json` from the orphan branch — useful after a fresh deploy completes.

## Troubleshooting

- **Empty graph**: `app.json` missing for the selected branch. The deploy workflow either hasn't run or `rad graph build` failed. Open the workflow run and check the "Build app graph" step.
- **Stale graph**: Click Refresh; if still stale, verify the latest deploy run actually committed to `radius-graph`.
- **PR diff doesn't appear**: PR head branch needs its own deploy run (workflow only runs on push to main by default unless a PR-trigger is added).
